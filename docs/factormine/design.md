# 分钟因子挖掘（factormine）设计草案

状态：草案，未实现。日期 2026-11-04。

## 1. 要回答的问题

之前的流程搜索（v2、P4、P5）搜的是整条交易流程的配置。菜单固定，随机搜索就能覆盖，LLM 没有优势。
factormine 换一个逻辑：LLM 写分钟级因子，合格的进因子库，最后用整个库去交易。要回答三个问题：

1. 在开放空间（写代码）里，LLM 找到合格因子的效率是否高于同一空间里的随机或遗传搜索？
2. 优势来自"能写任意代码"，还是来自"金融先验"？做法是拆成三个臂：LLM 写代码、LLM 写受限 DSL、随机写同一 DSL。
3. LLM 挖出来的因子库，加到现有 T1/T2 流程后，验证期的净收益是否更好？

## 2. 文献要点

| 工作 | 做法 | 对我们有用的结论 |
|---|---|---|
| FactorMiner（2026，清华） | A 股 10 分钟线；公式 DSL；先快筛 IC，再查与库的相关性，最后完整验证 | 入库门槛：\|IC\| ≥ 0.04–0.05，与库相关 < 0.5。替换规则：IC ≥ 1.3 倍且只和一个已有因子冲突。经验记忆把合格率从 20% 提到 60%。对照组含随机公式和 GPLearn。没有报告样本外衰减 |

| QuantaAlpha（2026） | 规划 → 假设 → 编码 → 回测 → 进化（变异、交叉） | 变异只改出问题的那一步；交叉组合两个父代里有效的部分。质量门：与假设一致、复杂度、冗余 |

| CogAlpha（ACL 2026） | 因子直接写成 Python 代码，进化搜索 | 认为代码比公式更有经济含义、更不冗余，但只有作者自己的对比 |
| AlphaBench（ICLR 2026） | 评测 LLM 在因子生成、评价、搜索三项上的能力 | 生成有效率 > 80%。**让 LLM 判断因子好坏，接近随机**。种群式进化搜索优于单链搜索 |
| FactorBench（2026） | 5 个市场比较 9 种挖掘方法，跟踪到组合层面 | 训练期 IC 高的方法，到验证和测试基本衰减光。LLM 方法没有稳定的样本外优势。**原始 IC 大多被风格暴露解释**：RD-Agent 原始 IC 0.025，残差只剩 0.001。没有随机对照 |
| AlphaMemo、Principle-level collapse（上一轮） | 记忆结构；161 次运行中 78% 收缩到单一思路 | 结构化记忆有用；多样性需要外部强制，不能靠提示词 |

文献普遍缺少的：同一空间的随机或 GP 对照加多种子、交易成本、残差 IC、事先冻结的阈值、一次性留出期。
这几点正好是我们已有的基础设施，也是这个实验可以做得更扎实的地方。

## 4. 因子的表示：分两段

1. **日内阶段** `intraday(m, d)`：输入每只股票每天的分钟线，只能用 bidx ≤ d 的数据，输出每只股票每天 1–3 个数。
   沿用现有自定义特征的沙箱和泄露检查。逐月计算，内存可控；结果按代码哈希缓存，复用时不必重算。
2. **日度阶段**：在日度面板上写表达式，可以用日内阶段的输出和前一天及更早的日线字段。算子包括时序类（ts_mean、ts_std、ts_rank、delta、ts_corr，窗口 5/10/20/60 天）和截面类（rank、zscore）。计算很便宜。

三个臂共用这一结构：

| 臂 | 日内阶段 | 日度阶段 |
|---|---|---|
| llm_code | LLM 写 Python（开放） | LLM 写 DSL |
| llm_dsl | LLM 写分钟 DSL（受限） | LLM 写 DSL |
| random | 随机或遗传生成分钟 DSL | 随机或遗传生成 DSL |

分钟 DSL 的组成：
- 时间窗口：开盘 30 分钟、上午、下午、尾盘 30 分钟、最近 k 根、到 d 为止的全部
- 条件：上涨的分钟、放量的分钟、接近涨跌停
- 字段：收益、成交量、成交额、相对 VWAP 的偏离、振幅
- 聚合：sum、mean、std、skew、占比、corr(x, y)、最大值出现的时间

常见的高频因子（尾盘成交占比、量价相关、日内收益偏度、聪明钱等）都能用它写出来。
比较 llm_code 和 llm_dsl，可以看出"开放代码"本身值多少；比较 llm_dsl 和 random，可以看出 LLM 的先验值多少。

## 5. 样本和标签

- **决策时点**：14:50（d = 230），和现有 T1、T3 一致。
- **主标签**：从 t 日 14:50–15:00 的 VWAP 到 t+1 日同一时段 VWAP 的收益，减去全市场等权均值。
- **副标签**：隔夜收益（收盘到次日开盘），用来服务 T2 的隔夜做 T。
- **股票池**：上市满 120 天、非 ST、当天没有停牌、成交额在前 70%。
- **快筛子样本**：固定 600 只股票。

## 6. 评估和入库（只由评估器决定，LLM 不打分）

事先固定的规则，写进配置文件并锁定哈希，和现有评估器一样：

1. **能否运行**：代码静态检查、能执行、通过泄露检查（截掉 d 之后的数据，因子值不变）、覆盖率 ≥ 80%。
2. **快筛**：在子样本和挖掘期上，Rank IC 的绝对值均值 ≥ 0.02，且每一年的符号都相同。
3. **完整评估**：在全股票池和挖掘期上计算以下指标。
   - Rank IC、ICIR、每年的 Rank IC、换手率（相邻两天排序的自相关）
   - 多空十分位扣成本后的收益
   - **残差 Rank IC**：先对规模、1/5/20 日反转、20 日波动率、换手率做截面回归，再用残差算 IC
4. **入库**：残差 Rank IC 的 t 值 ≥ 3，每年的符号都相同，与库内所有因子的 \|Spearman\| < 0.7。
   如果只和一个已有因子冲突，且新因子的残差 IC ≥ 1.3 倍，就替换它（FactorMiner 的规则）。
5. **新颖性**：和参考集算最大相关，只记录，不作为门槛。参考集是现有约 40 个原子特征加上经典高频因子。这个数也能看出 LLM 是不是在复述已知因子。
6. **多重检验**：账本记录每一次尝试。用随机臂的分布作为经验零分布，报告每个臂的尝试次数。

## 7. LLM 臂的搜索流程（吸取 P4、P5 和文献的教训）

- **机制目录加调度**：约 25 个经济机制，例如尾盘资金流、开盘冲击、日内反转或动量、量价背离、波动不对称、成交集中度、涨跌停附近的行为、隔夜和日内的分离、跳跃。用 Thompson 采样分配预算（复用 P5 的调度器），某个机制入库就加分，强制覆盖多个方向，防止收缩到同一思路。
- **种群式进化**：每轮从库和最近的候选中选父代，做三种操作：
  - 变异：只改一处，比如窗口、条件或聚合方式
  - 交叉：组合两个机制
  - 全新提案：在指定机制下从零写一个因子
- **经验记忆**：记录成功模式，也记录禁区，即因为和库内因子太像而被拒的方向。按机制检索后放进提示词。
- **批量提案**：每次调用出 4–8 个候选，评估器批量处理，省 token、提高吞吐。
- **代码报错时让 LLM 修复**：最多 2 次，修复也计入预算。
- **预算**：按"完整评估次数"计，同时记录 token 和耗时。

## 8. 因子库怎么用：最后在组合层面检验

- 每个会话得到一个因子库。合成方式有三种：等权 rank、按 IC 加权、LightGBM（复用现有模型代码）。
- 把因子库作为一个新的特征算子 `fmlib` 接入现有 pipeline，在 T1 持仓和 T2 底仓上做端到端回测，计入成本。
- 比较三种设置：只用现有特征、加 LLM 挖的库、加随机挖的库。

## 9. 对比实验

- **规模**：3 个臂 × 5 个种子 × 每会话 N 次完整评估（N 暂定 150，跑通后按耗时再定）。
- **指标**：
  - 每个臂的入库数，以及每入库一个因子花的 token 和时间
  - 库的多样性：覆盖了几个机制、库内平均相关
  - 验证期表现：库合成后的残差 Rank IC 和 ICIR，以及端到端净收益
- **统计检验**：种子之间的秩和检验，不用单次运行下结论。

## 10. 时间划分（需要你决定）

2024–2026 测试期已经开过一次，不能再用。

- **方案 A（推荐）**：挖掘期 2017–2020，按年分 4 折；2021 年用来选库和训练合成模型；2022–2023 作为留出期，最后只打开一次。
  2022–2023 在 v2 里当过验证期，但这次挖掘没用过它们。
- **方案 B**：挖掘期 2019–2021，和 P5 一致；2022 年用于选择；2023 年作为留出期，只有一年。

另一个风险：DeepSeek 的训练数据可能包含 2022 年之后的研报，它可能"知道"哪些因子在那几年有效。随机臂没有这个优势，所以如果 LLM 胜出，要注意它可能来自这种前视知识。结果要注明这一点，并报告入库因子和已知因子的相关度。

## 11. 工作量

- **代码**：DSL、计算缓存、评估、因子库、三个臂、脚本和测试，约 1–1.5 天。
- **跑实验**：先用 1 个种子小预算测出单次评估耗时，再决定 N 和通道数。
