# factormine 确认轮结果（2026-11-05）

结论：确认轮再次显著，LLM 搜索在小样本上优于随机搜索这一结论成立。
- **主指标**：两个 LLM 臂都显著优于随机臂（Holm 校正后 p = 0.012）。
- **库合成增量**：只有 llm_code 显著（p = 0.016）。

所以 llm_code 是证据最强的臂。最终结论还要等 2024–2026 留出期打开一次之后再下。

## 设置

- 代码冻结在 commit 427eff2，与第二轮相同；确认轮开跑前核对过，src 没有改动。
- 每臂用全新种子 8–12，共 5 个。会话名为 `pilot-<arm>-c-s<seed>`。
- 预算、门槛、标签、股票池与前两轮相同。
- 检验方法与第二轮一致：单侧 Mann-Whitney，Holm 校正。验证结果在 runs/factormine/validation_confirm.json。

## 怎么看

- **llm_code**
  - 在同样的候选预算下，找到的验证期合格因子大约是随机的 2 倍。
  - 合成后的验证期增量也约为随机的 2 倍。
  - 第一轮没有优势，第二轮的改动（修格式错误、机制先验、显示原始 IC）之后才拉开差距。
- **llm_dsl**：合格因子比随机多约 50%，但这些因子合成后没有带来更多增量，彼此之间或与预置因子的信息有重叠。
- **因子质量**：入库因子在验证期的保持率三个臂相同（93–95%）。LLM 的优势在于提出合格候选的效率，不在于单个因子更强。
- **成本**：llm_code 每个会话约 38 万 token、半小时；随机臂 5 分钟。如果按计算时间而不是候选数算预算，随机臂可以多跑很多候选，这个比较目前没有做。

## 局限

- 小样本：600 只股票，挖掘期只有 2020–2021。
- 调度先验用了第一轮 LLM 会话的挖掘期统计，是 agent 跨会话积累的经验，随机臂没有这类信息。
- 验证期 2022–2023 可能在 DeepSeek 的训练数据里。最终结论看 2024–2026 留出期，只打开一次。
- 还没有做端到端的交易回测（设计文档第 8 节）。

## 留出期的评估方法（打开之前写下）

- **只打开一次**：2024-01 至 2026-10。
  - 脚本是 scripts/factormine/fm_holdout.py，只在 `split.final_test_unlock` 里读数据，打开记录会写进 runs/locked_test_openings.jsonl。
  - 结果文件 runs/factormine/holdout_result.json 一旦完整，脚本就拒绝再跑。
  - 留出期的缓存单独放在 cache/factormine/pilot_holdout。
- **会话**：确认轮的 15 个会话，种子 8–12。因子、方向和库都沿用挖掘期的结果，不做任何调整。
- **主指标**：与前几轮相同，只是把验证期换成留出期。即每个会话找到的因子里，留出期方向与挖掘期一致、且 t ≥ 2 的个数。
- **检验**：两个 LLM 臂分别对随机臂做单侧 Mann-Whitney 检验，Holm 校正，p < 0.05 算成立。
  另外报告库合成增量的检验，作为辅助结论。
- 不论结果如何，都如实报告。打开之后不再修改 agent 和规则，也不重跑留出期。
